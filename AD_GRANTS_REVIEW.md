# Haleyouth Foundation, Google Ad Grants readiness review

**Reviewed:** 2026-05-10
**Site:** https://haleyouthfoundation.org
**Stack:** Next.js 16 static export, Firebase Hosting, Firebase Analytics (G-5RFZTEGFB9)
**Pages reviewed:** root layout, home, about, programs (index + slug), partners, impact, gallery, news, contact, get-involved (+ donate / volunteer / partner-with-us), privacy-policy, terms-of-service, plus Footer

The goal of this review is one thing: get the site through the Google Ad Grants policy review on the first attempt, then make it competitive enough that Ad Grants traffic actually converts to donations and volunteer sign-ups. The site is in good shape overall. The issues below are mostly cheap to fix and high-leverage.

I have grouped the findings by impact on the Ad Grants approval gate, not by where they sit in the codebase.

---

## 1. Hard blockers and likely-blockers for Ad Grants approval

These are items the Ad Grants policy team (or the automated pre-checks) actively look for. Each one is a real risk to first-attempt approval.

### 1.1 No `sitemap.xml` and no `robots.txt`

There is no `sitemap.xml` and no `robots.txt` in `public/` or generated by Next.js. Google's web crawler discovers pages without these, but Ad Grants reviewers and the Ads quality-score crawler explicitly look for both. Without a sitemap, ad landing-page quality is harder for Google to assess, and you cannot submit a sitemap to Search Console (which is itself a soft prerequisite for Ad Grants).

**Fix:** add two files in `src/app/`:

`src/app/sitemap.ts`
```ts
import type { MetadataRoute } from "next";
import { PROGRAMS } from "@/lib/constants";

const BASE = "https://haleyouthfoundation.org";

export default function sitemap(): MetadataRoute.Sitemap {
  const now = new Date();
  const staticRoutes = [
    "", "/about", "/about/our-story", "/about/leadership", "/about/global-recognition",
    "/programs", "/impact", "/partners", "/gallery", "/news", "/contact",
    "/get-involved", "/get-involved/donate", "/get-involved/volunteer", "/get-involved/partner-with-us",
    "/privacy-policy", "/terms-of-service",
  ].map((r) => ({ url: `${BASE}${r}`, lastModified: now, changeFrequency: "monthly" as const, priority: r === "" ? 1 : 0.7 }));

  const programRoutes = PROGRAMS.map((p) => ({
    url: `${BASE}/programs/${p.slug}`, lastModified: now, changeFrequency: "monthly" as const, priority: 0.6,
  }));

  return [...staticRoutes, ...programRoutes];
}
```

`src/app/robots.ts`
```ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [{ userAgent: "*", allow: "/", disallow: ["/admin/", "/admin"] }],
    sitemap: "https://haleyouthfoundation.org/sitemap.xml",
    host: "https://haleyouthfoundation.org",
  };
}
```

Then submit `https://haleyouthfoundation.org/sitemap.xml` in Google Search Console.

### 1.2 No phone number anywhere on the site

`SITE_CONFIG.phone` in `src/lib/constants.ts` is the empty string. The contact page shows only an email and a contact form. Ad Grants reviewers expect at least one verifiable channel of contact beyond email; a phone number is the strongest signal of organisational legitimacy. Many first-attempt rejections cite "insufficient organisational contact details."

**Fix:** add a Nigerian office line (even a Google Voice or VOIP routing to the founder works), put it in `SITE_CONFIG.phone`, and render it on the Contact page and in the Footer. If a public phone is not desirable, at minimum publish a verified office address with a photo of the office (you already have the Kogi State address, which helps).

### 1.3 No structured data (`Organization` / `NGO` JSON-LD)

Nothing in `src/app/layout.tsx` emits a JSON-LD block. Google's NGO and Organization schemas are how Ads (and Search) confirm the entity behind the site is a registered non-profit. The CAC registration number is in `SITE_CONFIG.registration` but only as a footer string. Reviewers cannot machine-read it.

**Fix:** add a JSON-LD `<script>` in `app/layout.tsx`:

```tsx
const orgLd = {
  "@context": "https://schema.org",
  "@type": "NGO",
  "name": "Haleyouth Foundation",
  "alternateName": "Haleyouth",
  "url": "https://haleyouthfoundation.org",
  "logo": "https://haleyouthfoundation.org/images/logo_l.png",
  "description": "Registered Nigerian non-profit empowering youth through mentorship, STEM education, and community development.",
  "foundingDate": "2019",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "Ateba Agassa-Okene",
    "addressRegion": "Kogi State",
    "addressCountry": "NG"
  },
  "email": "info@haleyouthfoundation.org",
  "telephone": "+234-XXX-XXXX",
  "identifier": "CAC RC-138260",
  "sameAs": [
    "https://www.facebook.com/haleyouthfoundation/",
    "https://x.com/HaleYouth_F",
    "https://linkedin.com/company/haleyouth-foundation",
    "https://www.instagram.com/haleyouthfoundation/"
  ]
};
```

Inject inside `<body>` via `<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(orgLd) }} />`.

### 1.4 Several pages have no `<title>` / `description` metadata

Pages missing explicit `metadata` in their `page.tsx`:

- `src/app/contact/page.tsx` (it is `"use client"`, so it cannot export metadata directly)
- `src/app/gallery/page.tsx` (also `"use client"`)
- `src/app/programs/page.tsx` (also `"use client"`)
- `src/app/admin/page.tsx` (admin, fine to skip but should be noindex)

The root layout sets a default, so pages without metadata fall back to "Haleyouth Foundation, Strengthening Youth Potentials" with no description override. Ad Grants quality score, Search Console, and the ads crawler all reward distinct per-page titles and descriptions.

**Fix:** these pages are client components, so split each into a server `page.tsx` that exports metadata and renders a client child component. Pattern (illustrated for `programs/page.tsx`):

```
src/app/programs/page.tsx              // server; exports metadata; renders <ProgramsClient />
src/app/programs/ProgramsClient.tsx    // "use client"; current page body
```

```tsx
// src/app/programs/page.tsx
import type { Metadata } from "next";
import ProgramsClient from "./ProgramsClient";

export const metadata: Metadata = {
  title: "Our Programs",
  description: "Twelve focused programs serving rural and underserved communities across Nigeria, from menstrual health and girls' education to STEM training and humanitarian response.",
};

export default function ProgramsPage() {
  return <ProgramsClient />;
}
```

Apply the same split to `contact/page.tsx` and `gallery/page.tsx`. Ten minutes of work per page, real Ads quality-score lift.

Suggested per-page titles and descriptions:

| Page | Title | Description |
|---|---|---|
| Contact | Contact Us | Reach Haleyouth Foundation about programs, partnerships, donations, or volunteer opportunities. Based in Kogi State, Nigeria. |
| Gallery | Gallery | Photographs from Haleyouth Foundation's programs across Nigeria and at the UN General Assembly SDGs Roundtable. |
| Programs | Our Programs | Twelve focused programs serving rural and underserved communities across Nigeria. |

### 1.5 Privacy Policy and Terms of Service are too thin

The current Privacy Policy (`src/app/privacy-policy/page.tsx`) is about 280 words. Google's Ad Grants reviewers explicitly look for: data controller identity and contact, what specific data is collected (cookies, analytics, IP, form data), the legal basis for processing, third-party processors named, data-subject rights (access, deletion, complaint), cookie-policy details, and a last-updated date. Yours covers most of these in summary but does not name the legal basis (Nigeria NDPR / GDPR if any EU traffic), does not name the analytics processor (Google Analytics 4 via Firebase), and does not mention cookies at all. Terms of Service is similarly skeletal.

**Fix:** expand to the seven required sections below. Keep the warm tone, but cover every category by name.

1. Data controller and contact (you, with email and address).
2. What we collect: form submissions, Firebase Analytics (cookies, page views, IP, device data), cookies from third parties (Paystack/Stripe if used).
3. Legal basis: NDPR consent + legitimate interest for analytics.
4. Named third-party processors: Google Analytics (Firebase), Stripe/Paystack, email sender (if any).
5. Data retention period (12 or 24 months for analytics, longer for donor records as required by Nigerian non-profit law).
6. Rights: access, rectification, deletion, complaint to NITDA (NDPR regulator) or supervisory authority.
7. Cookies: list cookie names and purposes, link to opt-out (Google's `_ga` opt-out browser add-on, or a simple banner; see §2.1).

### 1.6 No cookie consent banner

Firebase Analytics drops `_ga` and related cookies on first load. Nigeria's NDPR and GDPR (for any EU visitor) both require notice and, for non-essential cookies, consent. Ad Grants reviewers do not always flag this directly, but if Google's policy team checks the site against EU visitors and finds no consent UI, that is a meaningful soft-reject signal.

**Fix:** add a lightweight cookie banner. A few options:

- The `vanilla-cookieconsent` library is small, accessible, free.
- A custom Tailwind banner is fine for an MVP if it gates the Firebase Analytics init call until consent.

Either way, the Firebase Analytics initialiser in `src/lib/firebase.ts` should be wrapped so it only runs after the user accepts.

### 1.7 No `not-found.tsx` and no `error.tsx`

If the Ad Grants reviewer (or the ads crawler) hits a 404 or an exception, they see the default Next.js error page. That breaks the perception of a polished, in-control site and can affect ad approval.

**Fix:** add `src/app/not-found.tsx` and `src/app/error.tsx` with branded copy and clear navigation back to the home and programs pages. Make sure the 404 page also links to the donate flow, since 404 traffic is a real source of bounced donors.

## 2. Compliance polish (do these before submitting for Ad Grants)

These are not hard blockers but they are the difference between "approved on second attempt with a list of required fixes" and "approved on first attempt."

### 2.1 Admin route is in the sitemap risk

Footer has a discreet `<Shield>` link to `/admin/login`. The route is correctly excluded from `robots.ts` above, but the `/admin/login` URL is publicly linkable and crawlable today. Reviewers occasionally click it. The page should:

- Refuse to render any admin UI when the visitor is not authenticated.
- Carry a `noindex, nofollow` meta directive in its own page metadata.
- Not appear in the sitemap (the sample sitemap above excludes it).

### 2.2 Mission clarity on the home page

The hero rotates between six taglines, which is great for engagement, but Ad Grants reviewers want a single, scannable, above-the-fold mission statement. The current `AboutPreview` section addresses this but sits after the hero and the programs grid. Consider adding a short "Who we are, in one sentence" line below the hero, ahead of any visual flourishes. Example:

> Haleyouth Foundation is a registered Nigerian non-profit (CAC RC-138260, founded 2019) empowering youth through mentorship, STEM education, menstrual-health programs, and climate-resilient community development across Nigeria.

This single line answers every question a reviewer asks in the first ten seconds: registered non-profit, registration number, founding year, mission, geography.

### 2.3 Donation flow is unusually strong, but lacks tax-receipt language

The donate page is much better than most Nigerian non-profits' donation pages: multi-currency, copy-to-clipboard for account numbers, impact statements per donation level, programs to direct funds to. The two missing things that reviewers look for:

- A statement on whether donations are tax-deductible in Nigeria and which jurisdictions.
- A receipt promise (every donor will receive a written acknowledgement within X business days).

Both can be a single short paragraph at the bottom of the donate page or on a small "About donations" panel.

### 2.4 Image alt text quality

A spot-check of `AboutPreview.tsx`, `HeroSlider.tsx`, and team images suggests alt text is present but sometimes generic ("Haleyouth Foundation", "Team member"). Ad Grants approves on accessibility signals too; specific alt text is a small but cumulative quality signal. Rewrite a dozen of the most prominent images with descriptive alt copy ("Girls receiving reusable pad kits at Garki public school, Abuja, 2024").

### 2.5 No `<html lang>` switch on language detection (low priority)

`<html lang="en">` is correct for the current English-only site. If you plan to add Hausa, Yoruba, or Ebira content (per the LIFELINE and Pad-a-Girl plans), structure that with the `app/[locale]` pattern and `hreflang` tags. Not blocking for Ad Grants, but worth doing before scaling Ads spend.

### 2.6 Build / deploy validation

`firebase.json` sets `cleanUrls: true` and `trailingSlash: true`. That combination, paired with `output: "export"` in `next.config.ts`, can occasionally cause hydration mismatches and 404s on dynamic routes if the routing changes. After every deploy, smoke-test these specific URLs (they are the ones Ad Grants reviewers click most):

- `/`
- `/about/`
- `/programs/`
- `/programs/pad-a-girl/`
- `/contact/`
- `/get-involved/donate/`
- `/privacy-policy/`

Two of them should return < 200ms on a 4G connection. The current Lighthouse-grade animation work and Firebase Hosting should hit that comfortably.

## 3. Ad Grants performance levers (post-approval, but easy to set up now)

Once approved, Ad Grants requires you to maintain a 5% minimum CTR and meet other quality bars. Set yourself up now.

### 3.1 Conversions in Google Analytics 4

GA4 is wired up but I see no explicit conversion events in the codebase. Define and fire the following events in the donate, volunteer, contact, and newsletter flows:

- `donate_intent` (when the user clicks a donation amount)
- `donate_submitted` (after `submitDonation` completes)
- `volunteer_applied`
- `contact_submitted`
- `newsletter_signup`

Use the Firebase Analytics `logEvent` SDK or `gtag('event', ...)`. Once in GA4, mark them as Conversions. Ad Grants requires at least one valid conversion event tracking to maintain the account.

### 3.2 Landing pages by program

Ad Grants restricts ads to a maximum 5% CTR threshold and rewards keyword-relevant landing pages. Your program slug pages are already a great fit for this. Make sure:

- Each program slug page has a clear single CTA (donate to this program, volunteer for this program).
- Each has the program-specific stats and image, not generic copy. (You already do this; preserve it.)
- The URL is stable and indexed (the sitemap above includes them).

### 3.3 Branded campaign first

Once the Ad Grant is live, the first campaign should target your brand keywords (Haleyouth Foundation, Pad-a-Girl Nigeria, Haleyouth Climate Action) to lock those terms and produce the early conversions Ad Grants requires.

### 3.4 At least two campaigns and three ad groups

Ad Grants requires at least two active campaigns and three ad groups per campaign. Plan: one campaign for "Donate" intent, one for "Get Involved" intent. Each with three ad groups (one per programme cluster).

## 4. Small content fixes I noticed while reading

These are low-priority editorial items, not Ad Grants blockers.

- `app/privacy-policy/page.tsx` line 13: "Last updated: April 2026" is now stale. Add a tiny build-time injection so the page shows the current month, or update on every release.
- `app/terms-of-service/page.tsx` line 13: same as above.

- `Footer.tsx` admin login link uses `aria-label="Admin Panel"`. Good.
- `contact/page.tsx` "We'll get back to you within 24-48 hours." is a real commitment; make sure the inbox is monitored, since Ad Grants reviewers do email organisations to verify identity occasionally.
- `SITE_CONFIG.address` is `Ateba Agassa-Okene, Kogi State, Nigeria`. Add postal code if you have one; reviewers look for full postal addresses on NGO sites.

## 6. Honest probability estimate

Treat the following as a calibrated subjective estimate, not a measured statistic.

| Submission state | First-attempt approval probability |
|---|---|
| Submit today as-is | 35, 45% |
| Submit with §1 (hard blockers) fixed | 65, 75% |
| Submit with §1 and §2 (compliance polish) fixed | 80, 90% |

The base rate of Nigerian NGOs being approved for Ad Grants on first attempt is lower than the global average, because Google's policy team applies extra scrutiny to NGO eligibility in countries with higher fraud risk. The strong signals you already have (CAC registration on the home page, named UNGA representation, named institutional partners, working donation infrastructure, real impact statistics) all push the probability up. The missing items above are what bring it home.

If you fix items 1, 2, 3, 4, 5, and 9 first (call it the "minimum viable Ad Grants pack"), that is realistically ~3 hours of work and gets the probability to the 65-75% band. The rest is polish that raises the band further and helps long-term Ad Grants account health.
